# Highlightr

> [!info] Included plugin — enable it to try this
> Enable the included **Highlightr** (`highlightr-plugin`) for this exercise. Reference version: **1.2.2**. Minimum Obsidian: **0.12.8**. See [[00 Start/Install community plugins]].

The included Highlightr palette adds three useful labels: **Evidence**, **Question** and **Risk**. [[80 Sandbox/Plugin lab/Reading review]] contains a prepared annotation pass, and [[80 Sandbox/Plugin lab/Reading review practice]] supplies the clean version.

## Annotate with a purpose

In a copy of the practice note, select the observation sentence and choose Evidence through Highlightr. Use Question for the unanswered teaching question and Risk for the earlier-plan assumption. Compare the result with the prepared version.

**Expected:** the stored inline `<mark>` elements retain the selected color. The palette gives a reading convention; it does not validate a sentence or change a resource's status.

## Revise or remove an annotation

Change the wording of a question into an actual observation before recoloring it. Use Highlightr's available unhighlight action on the marked selection, or inspect the complete saved mark in Source mode when changing it. Compare with Undo and the native `==highlight==` syntax.

## Turn a useful annotation into knowledge

Extract one passage with Note Refactor and keep a link to the source. Classify it as a Resource only if it belongs in the library, and deliberately write a flashcard if you want to study it. None of those records are created by the color itself.

Inline colors depend on the host's HTML/style support. The prepared notes make it possible to distinguish a missing rendered color from missing saved markup. Remove practice copies to reset; the palette and annotated reference can remain for the next reading session.
