# Heading chains, code/table IDs, batch rename and vault trash, 2026-11-15

Accepted bounded workflows on Windows desktop and actual-folder WASM. This iteration completes four additional roadmap subsets while preserving the prior authoring/organization and CI attachment-path fixes.

## Delivered behavior

- **Create heading chain** explicitly previews every missing document-level ATX heading. A wholly missing chain creates H1/H2 and subsequent levels at EOF. A unique existing ancestor prefix is reused, and only the missing suffix is inserted at the end of that subtree before its next sibling. All prefixes must resolve to their expected positions; ambiguous, shadowed, unsafe, unclosed or deeper-than-H6 chains refuse. Ordinary missing-heading Enter remains source-only. Same-note headings plus link share one Undo; cross-note creation uses one normal versioned target write before guarded source insertion. Source Undo keeps the other note's complete chain. Later source/cleanup failures retain acknowledged headings and report that outcome; newer observed target bytes are preserved.
- Block-ID authoring adds whole closed top-level fenced-code blocks and GFM tables to the supported prose/list/task/quote set. Standalone markers resolve to the exact complete container, including an EOF table. Literal code cannot trigger completion; a query inside a table excludes its entire owner. Metadata corrects CRLF tables through an equal-width projection while preserving exact original UTF-16 offsets and the ordinary source syntax tree. Existing inline and child-ID positions remain intact. Both editing modes retain isolated same-note Undo and guarded cross-note writes.
- **Files → Select notes → Rename selected notes** reviews 1–20 Markdown notes in their current folders. Literal case-sensitive replace-all and optional prefix/suffix preserve extension spelling. Every selected name must change. Review lists exact old → new paths; editing a field or the Markdown/Canvas link option invalidates it. Unsafe, duplicate, occupied and case-only destinations, swaps and rename chains refuse without generated filenames. Projected paths also refuse closing brackets, backticks, surrounding component/stem whitespace and unbalanced parentheses that the existing link rewriter cannot safely round-trip. Normal sequential renames preserve the open editor and update ordinary Markdown/wiki and Canvas file/text-card references when enabled. A later failure reports the completed count and keeps earlier names; a new selection is required to retry.
- **Files → Select notes → Trash selected notes** reviews 1–20 saved Markdown notes and exact current versions without saving drafts. Confirmation uses normal staged-view, versioned vault-local trash operations. Dirty/saving/reloading selections and newer physical versions refuse. Only successful backend acknowledgements count as confirmed removals, including when later cleanup fails; independent disappearance and lost transport acknowledgement do not imply success. Removed-note views close, exact BOM/CRLF/Unicode copies remain in physical .trash, incoming links may become unresolved, and attachments remain in place. A later failure keeps earlier trash copies and reports partial confirmation without replay. Recovery is manual; this action is not editor Undo and does not follow permanent/system-trash preferences.

Read-only cached vaults keep rename and trash visibly disabled while note selection/opening remains available. All four authoring/mutation workflows refuse cached writes, retaining exact blobs and zero API/raw requests. Selections remain per-pane transient state and reset at restart.
