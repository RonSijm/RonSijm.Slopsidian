The WASM app operates on the selected files; it does not upload a vault to
GitHub Pages or import it into a disposable browser copy.

Changing from a `github.io` origin to `slopsidian.md`, or changing the base path,
can make previously stored recent directory handles unavailable to the new
site context. Use **Open a folder** and grant permission again. The actual vault
files remain on disk.

## Exact supplied release boundary

The user selected **standalone WASM with explicit browser limitations**, not a
native companion. A desktop-shaped browser UI is still not Electron:
`Platform.isDesktop` describes UI mode and `Platform.isDesktopApp` describes
the Electron application. Neither flag is falsified to skip required code.

Unavailable module requests still throw. The host records them per
plugin/vault and shows an explanation even when a plugin catches an optional
dependency internally; portable fallbacks are not forcibly disabled.
Raw known vendor/runtime errors remain in the reports, while unrelated console
errors and uncaught runtime exceptions fail the exact-release acceptance.
No `util`/HTTP/process placeholders, native service, plugin-byte patches or
substituted releases hide these restrictions.

## Shared Modal keyboard accessibility

The same [light-DOM dialog keyboard subset](../Features/MODAL-ACCESSIBILITY.md)
passes desktop (sixteen checks, three sessions, fifty-nine bound artifacts)
and standalone WASM (twenty-eight checks including thirteen bootstrap checks,
twenty-two assets and thirty-one scenario/source inputs). Both use real
Tab/Shift+Tab/Escape/Enter input and computed accessibility-tree names. The
browser uses the real folder picker and handle reconnect with no native
companion. Existing Menu and suggestion suites pass on both hosts. Complete
screen-reader/OS/native-dialog and shadow/frame/media interior behavior remain
separate; native Web viewer support remains unavailable in WASM.

## Shared modal viewport containment

The same [responsive shared-dialog stylesheet](../Features/MODAL-LAYOUT.md)
passes seven layout groups on desktop (eight checks, three sessions, fifty-eight
bound artifacts) and standalone WASM (twenty checks including thirteen bootstrap
checks, twenty-two assets and thirty inputs). Real pointer/keyboard input is
used at 320×568, 640×240, 320×240 and 1280×800 renderer CSS viewports. This does
not establish physical OS-window/display/browser zoom or virtual-keyboard
behavior. Drafts, exact note bytes and unrelated plugin enablement survive the
exercised resizing and native restart / actual-folder browser reconnect. Both
hosts also renew the existing keyboard, Note composer/Menu and suggestion suites.
